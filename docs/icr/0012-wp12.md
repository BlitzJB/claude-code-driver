## API the kernel (WP-11) uses

- `launchSession(ports, config, {sinks:{hook, tail, observe, warning}, hookTransport?, httpSelfTestFailedRecently?, followTail?,
  registerExit?, registryCrossCheck?, reap?, ownerPid?, distCliPath?})` runs §3.1 steps 1–13 and returns `{handles, lifecycle, …}`.
  On failure it tears down in reverse order and throws a `CcdError`.
- `SessionLifecycle`: `close(opts, ctx)` (§3.8 steps 0–9, `ctx` supplies the core-coupled callbacks), `finalizeAfterExit()`,
  `markReady()`, `persist(RegistryPatch)` (the `registry.persist` intent; `patch.state` is stored as the record's `status`),
  `signal(sig)` (the `process.signal` intent, identity-verified), `killSync()`, `registerExit()`, `startHeartbeat()` (A-1).
- `reaper.ts` exports `reap`, `classifySession` (lifecheck classes), `verifyClaudeIdentity`, `terminateVerified` for WP-16.

## Deviations from DESIGN.md §3.1–§3.8 (with reasons)

1. **Step order 9 before 8:** the hook server starts before the network sidecar, so the sidecar gets our hook port in
   `denyPorts` (SEC §6.3). Nothing observable by Claude changes; both run before the settings file and the spawn.
2. **Step 12a before 11:** `tmux.probe` and `tmux.create` run before the registry record is written, because the record needs the
   probed tmux path and the server's socket path. The record (`state:'launching'`) is still written **before** `spawnPane`.
3. **`--system-prompt-file` / `--append-system-prompt-file`** are rejected (`E_FORBIDDEN_ARG{reason:'notInHelp'}`): the recorded
   `claude --help` 2.1.316 does not list them. They become accepted once a recorded `--help` lists them (§3.3 rule).
4. **LP-52 key-mode check:** `PaneStatus` does not expose `#{pane_key_mode}`. The L0 server checks it right after spawn and throws
   `TmuxUnsupported{reason:'extendedKeys'}`; the launcher maps it to `E_TMUX_UNSUPPORTED{reason:'extendedKeys'}`.
5. **P-TMUX-50:** a missing `tmux-256color` terminfo on Linux is a warning only; the server's `default-terminal` is owned by L0 and
   no port option exists to switch it to `screen-256color`.
6. **`keepClaudeDebugFile`:** there is no file-move port, so the whole 0700 session dir is kept and the archive entry is marked
   `keptSessionDir:true` (the dir sweep skips it).
7. **Reaper file ops:** socket unlink and the socket-dir count use `ProcessPort.exec` of `/bin/rm -f --` and `/bin/ls -1 -A --`
   on validated absolute `ccd-*` paths (no unlink/readdir port exists for arbitrary paths).
8. **Tail at launch:** `followMain` runs at launch only when a `sinks.tail` listener is attached (a listener-less follow would lose
   a resume's replayed history); otherwise the core's `tail.followMain` intent on SessionStart starts it.
9. **Owner-watch start failure fails the start** (`E_INVARIANT`): D-28 is fail-closed.
10. `claude auth status` timing out maps (via `errors-map.ts`) to `E_STARTUP_TIMEOUT`, not `E_LOGIN_REQUIRED`.

## Verifier additions (2026-11-03)

11. **P-SEC-31 (settings tamper):** `SessionHandles.settings {path, sha256}`; `SessionLifecycle.verifySettingsIntegrity()`.
    The launcher re-checks the sha256 on every `SessionStart` hook event. A mismatch (or a read error) → warning
    `E_SECURITY_SETTINGS_TAMPERED{reason:'settingsTampered'}` and `failClosed(…, {immediate:true})` (verified SIGKILL). If this
    happens before `launchSession` returns, the launch fails with that code and tears down (Claude is killed before the hook
    server closes). The spec asks for a `security.alert` domain event. No observation kind can carry it from L3 to the core, so
    for now L3 raises it as a launch warning. Getting a real `security.alert` needs an additive `model/observation.ts` kind plus
    core handling (WP-00/WP-09).
12. **Fail closed on sidecar / hook worker death (P-NET-25, §3.10, §3.5):** the reserved `sidecarDied` net record, or the
    concrete transport's `onDied` (ICR 0003 `HookTransportExtras`, duck-typed because the port lacks it) → warning
    `E_NETWORK_UNAVAILABLE{sidecarDied}` / `E_HOOKS_UNAVAILABLE{hookWorkerDied}` and `failClosed` (verified SIGTERM →
    SIGKILL). The pane death then takes the normal exit path. The guards are cancelled at teardown (`addGuard`).
13. **Launch undo `claude.terminate`:** a failure after the identity check terminates the verified Claude pid before
    `tmux.kill`. A single kill-server SIGHUP is not trusted (P-LIFE-11, P-TMUX-61).
14. **Reaper, `launching` records with no Claude pid:** `list-panes -a -F '#{pane_pid}'` on the record's own server. Each pid
    whose command contains the exe basename and the argv session id is terminated (verified) before kill-server.
15. `lifecheck-target.json` `distPath` now comes from `fileURLToPath`, so it is not percent-encoded.
