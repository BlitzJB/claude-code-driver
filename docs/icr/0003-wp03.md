# ICR 0003: WP-03 hook transport — no model change; one proposed port addition and two recorded readings

- **Status:** WP-03 note (2026-11-03). No file outside `src/platform/hook-server/**` and WP-03's tests was edited.
- **Files:** `src/platform/hook-server/**`, `test/unit/platform/{hook-server,forwarder}.test.ts`,
  `test/contract/hooks.contract{,.test,.helpers}.ts`, `test/contract/standalone.test.ts` (forwarder part),
  `test/contract/claude-hook-client.test.ts`.

1. **Proposed additive change to `src/platform/ports.ts` (WP-00 owns it; not applied).** §3.5 says a hook-worker exit is
   `HookWorkerDied` → `channel hooks down` → the pane is killed, and SEC §2.3 says a burst of 403s raises
   `security.alert E_SECURITY_HOOK_FORGERY`. The §2.7.5 `HookTransport` has no channel for either. The concrete
   `NodeHookTransport` and `FakeHookTransport` therefore implement `HookTransportExtras` (exported from
   `hook-server/transport.ts`):
   `onDied(fn: (err: HookWorkerDied) => void): Cancel`, `onForgery(fn: (b: {count, windowMs, lastReason}) => void): Cancel`,
   `detailedStats()`. Proposal: add `onDied?` and `onForgery?` as optional members of `HookTransport` so `session/**`
   (type-only access to `ports.ts`) can subscribe without knowing the concrete class. Until then WP-INT
   (`runtime/node.ts`) can wire them, because runtime may import platform. `HookWorkerDied` has the stable
   `name = 'HookWorkerDied'` so `session/errors-map.ts` can map it by name.
2. **`closed` reasons.** `RawHookEvent.closed` resolves `'timeout'` when the forwarder was terminated by a signal while held
   (Claude's hook timeout or a turn abort; the forwarder sends `{"v":1,"abort":"signal"}` before exiting), and
   `'client_gone'` when the connection closed without that line (SIGKILL, crash). Both are "Claude stopped waiting";
   `'timeout'` does not prove it was the hook timeout and not an abort (LP-08 can refine this).
3. **Worker closure (reading of §1.2 vs §1.4 3c).** §1.2 lists `auth.ts`, `body.ts`, `http-server.ts`, `unix-server.ts` as
   separate files, while §1.4 3c / the depcruise rule allow `worker.ts` to import `node:*` only. All five files import
   `node:*` only (plus erased `import type`), and `worker.ts` loads the four server modules with a computed
   `import(new URL('./<name>.js', import.meta.url))` (`.ts` when running from src under Node's type stripping), injecting
   auth/body into the servers. The worker's whole runtime closure is builtins-only, works from `dist/` without a bundler
   (P-API-13), and a unit test asserts both the builtins-only imports and that each module matches the shape `worker.ts`
   expects.
