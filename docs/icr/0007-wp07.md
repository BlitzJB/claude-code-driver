# ICR 0007 (WP-07): screen classifier, profile tables, and the conventions consumers rely on

- **Status:** accepted (2026-11-03, WP-07, additive only)
- **Model change (§8 ICR rule):** `src/model/screen-facts.ts` adds the `ScreenFacts.surface` member `'editorOpen'`. This is ICR 0001 item 3a (LP-01): Claude puts the pane on the alternate screen during the external-editor handoff, even with `CLAUDE_CODE_DISABLE_ALTERNATE_SCREEN=1`. Core (WP-09) treats it as transient (ICR 0001 item 3c). It never degrades the screen channel and never starts a claim.

## Additive L1 surface (my files only; §2.8 names are unchanged)

1. `classifyFrame(lines, status, profile, ctx?)` takes an optional 4th argument `ClassifyContext { at?, wallAt?, editorPhase? }`. `at` and `wallAt` fill `ScreenSnapshot.at/wallAt`, which §2.8 declares but the 3-argument signature cannot supply. `wallAt` is the base that reset texts resolve against. `editorPhase:true` means "this capture was taken while an `editorStage`/`awaitEditorConsumed` phase was active". With it, `alternate_on==1` gives `editorOpen` (ICR 0001 item 3b). Without it, the frame is `unsupportedRenderer`.
2. `ScreenSnapshot` has two extra fields. `editorHint` is true when `ctrl+g to edit in …` is visible. `autoContinueLine` holds the usage-limit auto-continue line, if there is one.
3. `ScreenDebouncer` has three extra methods:
   - `frozen()`: the P-SCREEN-27 diagnostic. The last emitted frame is a spinner and its `frameHash` has not changed for at least `frozenAfterMs`, measured on `Capture.at`.
   - `last()`
   - `telemetry()`: push/emit counts, plus distinct `none`-while-busy status lines and `unknownModal` bodies, at most 64 of each (P-SCREEN-24).

   The debouncer also adds the history fallback of ICR 0001 item 3b. An alternate-screen frame is `editorOpen` when it follows a `main` frame and either the alternate screen is blank or that `main` frame showed the editor hint. Once a frame is `editorOpen`, later alternate-screen frames stay `editorOpen` until the alternate screen ends.
4. `createScreenChannel({frozenAfterMs, profile}).push(capture, {wallAt, tz, editorPhase?})` runs classify and debounce in one call. If a raw capture has the same `Capture.hash`, the same pane status and the same editor phase as the previous one, the classifier is skipped (P-SCREEN-23), but the frozen detector still advances. **WP-13 `pollers.ts`** should use this helper and pass `editorPhase`. Per ICR 0001 item 3d, the executor does not capture during `awaitEditorConsumed` at all.

## Profile files

`profiles/claude-2.1.316/{screen,errors,commands}.ts` keep their fixed exports. Following WP-06's `hookExtras` pattern, each file also exports the vocabulary that the assembly type has no slot for: `screenExtras`, `errorsExtras` and `commandsExtras`. Callers pick the right one by version with `screenExtrasFor(profile)` and `errorsExtrasFor(profile)` from `channels/screen/classify.ts`.

- `statusOrder` is now `stalled, noResponse, autoModeUnavailable, lowPriority, retryingReset, retrying, retryingUnparsed, spinner, done, waitingBackground, interrupted`.
  - `hookWait` is a spinner paren segment, not a kind of line.
  - `retryingUnparsed` is the tier-A fallback (`✻ … · attempt n/m`). It lives in `screenExtras.statusFallbacks`.
- **Commands (ICR 0001 item 6, P-REV-02).** The alias table holds every alias VERIFIED-BIN in 2.1.316, not just the five in §3.6. Among them:
  - `/cost`, `/stats` → `/usage`
  - `/continue` → `/resume` (refused)
  - `/checkpoint`, `/undo` → `/rewind` (refused)
  - `/update` → `/restart` (refused)
  - `/settings` → `/config`
  - `/bashes` → `/tasks`
  - `/allowed-tools` → `/permissions`
  - `/plugins`, `/marketplace` → `/plugin`
  - `/name` → `/rename`
  - `/bg` → `/background`

  The allow, deny and refuse lists use canonical names only. The allowlist entry `/cost` is now `/usage`. The denylist entries `/bashes` and `/settings` become `/tasks` and `/config`. `/rewind` is in `refusedAlways`. `commandsExtras.canonical(name)` and `commandsExtras.classify(name)` return one of `allowed`, `unsafe`, `refused` or `invalid`. `commandsExtras.immediate` lists the `immediate:!0` commands (VERIFIED-BIN). **WP-09** should use these helpers rather than re-deriving the rules.

## Semantics consumers need (WP-09 core, WP-12 launcher, WP-13 executors)

- `usageLimit.limitName` is the `rateLimitType` key when the label is known (`five_hour`, `seven_day`, `seven_day_opus`, …). The legacy `session limit` label maps to `five_hour`. An unknown label is passed through as-is, for example `monthly spend limit`. `usageLimit` is also set when only an auto-continue line is visible, such as `Press enter to continue` (`autoContinue:'stalePressEnter'`).
- `status.resetText` and `resetsAtWall` on a `retrying` status come from the `(<reset>)` form (LP-30, UNVERIFIED live). That form also forces `errorHint:'rateLimit'`.
- `composer.empty` means "no typed text is believed present". It is true when the composer text is blank, and also when only a placeholder or ghost text is showing (`placeholderLikely` without `pastedPlaceholder`). In an `-e` capture, `composer.text` holds only the non-dim text.
- Gates and exits:
  - `dialog.gate` carries the gate kind, and `dialog.title` holds the line that matched.
  - Pre-UI exit strings map as follows:
    - `Session ID … is already in use` → `sessionInUse`
    - `No conversation found …` → `resumeDialog`
    - invalid UUID, `could not start`, and the org min/max version policy → `other`

    WP-12 refines the error code from `title`.
  - A dead pane is `exited` unless a gate string is visible.
- `survey` stays on the `main` surface, as `dialog.kind:'survey'`, because the input box is still there (P-SCREEN-30). The rewind picker is `modal` with `dialog.kind:'rewind'`. Elicitation, plan-approval and question dialogs have no strings yet (LP-46/LP-51), so they classify as `modal` or `unknownModal`.
- `frameHash` covers only the bottom region: from the topmost scanned row of the last block or status down to the end of the pane, plus the pane flags. Conversation scrolling above that region never re-emits a frame.

## Verifier amendments (2026-11-03, WP-07 audit; additive, WP-07 files only)

- `ScreenSnapshot.rendererUi?: true` is set when an alternate-screen capture draws Claude's own rule–❯–rule input box, which means the fullscreen renderer is active. Such a frame is always `unsupportedRenderer`, even when `editorPhase` is true. The debouncer's history fallback never rescues it. The editor chain also breaks at the first `unsupportedRenderer` frame, so a blank alternate frame after it is not `editorOpen` (P-SCREEN-20, LP-01).
- On a live pane, the permission dialog check runs **before** the trust and startup-gate checks. A permission dialog is a numbered option plus a `Do you want to …?` question, and the question must not itself be a gate line. Because of this order, a tool input shown in the dialog body cannot turn the dialog into a trust or startup gate (P-REV-29, P-SEC-34). For example, a Bash heredoc that prints `Accessing workspace:` stays a permission dialog. The API-key gate question (`Do you want to use this API key?`) is still classified as `startupGate{apiKey}`.
- A survey on the main surface is read only from the ≤ 6 non-decoration rows next to the input box. A tool-output line further up that reads `How is Claude doing this session?` is not a survey.
- Version-specific regexes that were inline in `regions.ts`, `classify.ts` and `to-facts.ts` now live in `screenExtras` (§2.8 L1 rule). They are `slashMenuRow`, `noResponseWaited`, `attemptSuffix`, `waitingAgents` and `waitingWorkflows`.
