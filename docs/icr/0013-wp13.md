# ICR 0013 (WP-13): L3 executors — wiring contract for the kernel (WP-11) and launcher (WP-12)

- **Status:** accepted (2026-11-03, WP-13). **No change to `src/model/**` or `src/platform/ports.ts`.**
- **Files:** `src/session/{input-executor,permission-broker,path-resolver,pollers,tail-driver}.ts`, their unit tests, and
  `test/contract/input-executor.contract.test.ts` (executor + pollers against FakeTmux and real tmux on `ccd-ct-*` sockets).

Every executor takes an `emit: ObservationSink` (`(o: ObservationInput) => void`, exported from `input-executor.ts`). The kernel
queue stamps `seq`. Every `execute()` returns a promise that never rejects, and nothing is emitted after `close()`.

| Intent kind | Executor | Observation(s) emitted |
|---|---|---|
| `input` | `createInputExecutor({clock, pane, editor, emit, profile, redact?, chunkGapMs?, escGapMs?})` | `input.done` |
| `screen.captureNow`, `poll.cadence`, `auth.poll` | `createPollers({clock, pane, emit, profile, tz, editorGate?, auth?})` | `screen.frame`, `auth.status`, `channel.health{screen}` |
| — (A-3, call `pollers.watchPane()` once the pane exists) | pollers | `process.exited` (once) |
| `host.askPermission`, `host.cancelAsk`, `hook.respond`, `hook.armSelfTest`, `hook.disarmSelfTest` | `createPermissionBroker({clock, hooks, emit, dispatch, getState})` | `hook.responded`, `hook.selfTestArmed`, `permission.hookClosed`, `channel.health{hooks}` on an arm failure |
| `permission.resolvePaths` | `createPathResolver({clock, fs: EnvPort, cwdRealpath, emit})` | `permission.pathsResolved` (never an empty `paths` list) |
| `tail.*` | `createTailDriver({clock, tail, emit, profile})` | everything the L1 transcript normalizer returns, `channel.health{transcript}` |

Notes for the kernel owner:

1. **Feed every `RawHookEvent`** to `broker.trackHookEvent(raw)` (watches `closed` on held PermissionRequests, §3.7 step 7) and to
   `tailDriver.noteHookEvent(raw)` (pokes the tail; a new absolute `transcript_path` for an already followed session goes to
   `observePath`, P-TAIL-23).
2. `kernel.setPermissionHandler(h)` → `broker.setHandler(h)`. The broker calls `dispatch({type:'permission.answer', by:'handler'})`.
   A handler result of `undefined`, or no handler, does nothing: the host answers through the `permission.requested` event.
   `execute(host.askPermission)` resolves once the handler has **started**, not when it returns. User code may never
   return, and a kernel that executes intents in order must still deliver the `host.cancelAsk` that aborts it. `broker.idle()`
   waits for running handlers (tests, close).
3. Pass the input executor to the pollers as `editorGate`. While `awaitEditorConsumed` is pending the pollers take no capture
   (ICR 0001 item 3d). Captures taken during an editor phase are tagged so the classifier reports `editorOpen` (item 3b).
4. `pane` is a getter, so the executors can be created before the launcher spawned the pane. Before that, input fails with
   `E_SESSION_EXITED{noPane}` and captures are skipped.
5. `redact` for `captureText` should be `session/redact.ts` (WP-11). The default is identity.
6. `hook.armSelfTest`/`hook.disarmSelfTest` live in the broker, because it owns the `HookTransport` handle. On an arm failure it emits
   `channel.health hooks degraded{selfTestArmFailed}` and never a false `hook.selfTestArmed`.
7. Path-resolver rule detail: `Grep.pattern` is a regex, not a path, but §3.7 step 1 lists only `Grep.path` and `Grep.glob` as
   known. So a Grep regex that contains `/` is `unknownArg`, and `allowRead` falls back to `ask` for it. This is conservative and
   as written. A relative `file_path`/`path` is resolved against `cwdRealpath`, and a leading `~` is never expanded (`tilde`).
   Glob/Grep patterns are checked on every brace expansion (bounded to 256, beyond that `unknownArg`), after backslash
   escapes, per whitespace/comma list item and with a leading `!` stripped. So `.{.,}/x` (expands to `../x`), `{\/etc/*,x}` and
   `*.ts /etc/*` are refused.
8. `PermissionAsk.background` follows the core's §3.7 step 10 rule (`isBackground` in `decide/permissions.ts`): the request
   carries an agent, or its bound tool belongs to a background agent. So the handler's `deadlineAt` and `background` agree.
9. Pollers measure the next screen tick from the end of the last *attempt* (success, failure, skipped editor tick, no pane),
   so a failing capture can never re-arm at `now`. An `auth.poll` that arrives during a run takes effect when the run ends.
