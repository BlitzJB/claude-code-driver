# ICR 0002: WP-06 additive model change and readings of §2.4/§2.8

- **Status:** accepted (2026-11-03, WP-06, additive only)
- **Files:** `src/model/observation.ts` (one new union member); WP-06's own files `src/channels/{hooks,transcript}/**`,
  `src/channels/profiles/claude-2.1.316/{hooks,transcript}.ts`

1. **New observation `prompt.blocked{reason, text}`** (ICR 0001 item 4, LP-47 VERIFIED-LIVE). A hook-blocked
   `UserPromptSubmit` writes no `user` entry, no `ai-title` and no history line; it writes one `system` entry with
   `subtype:'informational'` and `promptSubmitEnding.ending.kind:'blocked_by_hook'`, whose `content` is
   `"UserPromptSubmit operation blocked by hook:\n<reason>\n\nOriginal prompt: <text>"`. The transcript normalizer maps that
   entry (and only that one; other informational notices are ignored) to `prompt.blocked`, with `reason` from
   `ending.reason` (falling back to the content) and `text` = everything after `Original prompt: `. `promptKept` is never
   read (it is written `false` although the text returns to the composer). **WP-09:** use it as transcript evidence for
   `E_TURN_BLOCKED_BY_HOOK` (§3.6 step 6) and to cross-check the self-test ack (`reason` is our constant block reason, `text`
   the nonce); treat any `prompt.blocked` whose text is the armed/recent nonce as part of the self-test, never as a Turn.

2. **Several observations from one transcript line get distinct `meta.uuid`s.** A tool_result line yields `tool.result` and
   `permission.decisionRecorded` (RC §2.2), an aborted text block yields `message.block` and `turn.interrupted`, a validation
   error yields `tool.result` and `tool.validationError`. The first observation of a line carries the entry uuid, the n-th
   (n ≥ 1) carries `<uuid>#<n>`; `origin.entryUuid` always holds the raw entry uuid. The keys are deterministic, so the
   per-generation uuid de-dup (D-42) still absorbs a full rescan after a rewrite and never drops a sibling observation of
   the same line. `api-request` lines use `txreq:<id>` (§2.4). Metadata records carry no uuid and are folded last-wins in
   the normalizer (only `permission-mode`, `last-prompt` withdrawal, `continued-in` and `relocated` produce observations,
   each only on change; `queue-operation` is never folded).

3. **Version-specific vocabulary outside the assembly type.** `ClaudeProfile['hooks'|'transcript']` (WP-00, fixed) has no
   slot for payload field names, tag names, notification types or the LP-47 strings. They live in the same profile files
   as the named exports `hookExtras` / `transcriptExtras` and are selected by `profile.version` inside
   `channels/hooks/normalize.ts` / `channels/transcript/normalize.ts`; the normalizer signatures of §2.8 are unchanged.
   `hookExtras` also records `optInEvents: ['PostToolBatch']` (P-HOOK-48: not in `hooksProfile.observationEvents`),
   `switchableEvents: ['PreToolUse','MessageDisplay']` and `timeoutsSec {default:5, MessageDisplay:3}` for WP-12's
   settings plan.

4. **Readings of §2.8.** `createTranscriptNormalizer(profile, opts?)` takes an optional `opts.now()` time source: non-line
   `TailEvent`s carry no read time, so their observations use L3's clock (or the last line's read time without one).
   The returned object also has `stats()` (lines, observations, ignored, unknown, dropped) for the L3 counters. The FileKey
   string form is `main:<sessionId>` / `agent:<sessionId>:<agentId>` (`fileKeyString` in `transcript/file-state.ts`), used
   for `origin.fileKey` and `resetFile`. `normalizeHook` returns `rejected:'eventMismatch'` with no observation when the
   payload's `hook_event_name` differs from the routed event, and `rejected:'malformed'` plus one `unknown{channel:'hook'}`
   observation (so the hook still counts as channel liveness) when the body was truncated, is not an object, or lacks a
   field the event's observation needs. A UPS without `prompt_id` gets `promptId:''`; `permission_mode` on any event also
   yields `mode.observed` (`manual` → `default`, P-DOCS-03). `transcript.relocated.newPath` is the path the tail last
   reported for that file (`moved`/`opened`), falling back to the entry's `relocatedCwd` (the stamp carries only the cwd).
   Tail `error` events become `unknown{channel:'transcript'}` (channel health stays an L3 fact); `torn-tail` becomes
   `transcript.file{event:'malformed', detail.reason:'torn-tail'}`; a subagent `missing` also yields `agent.fileMissing`.

5. **Verifier amendments (WP-06 verification pass, same day, no model change).** (a) `normalizeHook` is wrapped like the
   transcript `push`: an internal failure (for example a hostile accessor in a payload) returns `rejected:'malformed'`
   and one `unknown{channel:'hook', raw.reason:'normalizerError'}`, never a throw (P-REC-20). (b) A payload with
   `teammate_name` but no `agent_id` gets `AgentRef{agentId:'teammate:<name>', teammateName}` (§4.5.9 key), so teammate
   tools and messages never attach to the main thread. (c) An entry-level `permissionDecision` or `toolDenialKind` on an
   entry with several tool results is not attributed to any of them (`permissionDecision` counted as dropped). (d) The
   profile markers that the core cannot see are now applied in L1: a single error tool result whose text starts with
   `userRejectedToolResultPrefix` and has no `toolDenialKind` gets `denialKind:'user-rejected'`, and a user entry starting
   with `safetyClassifierStop` but missing `refusedMessageId` is `prompt.recorded{isMeta:true}`. (e) A `relocated` stamp
   without `relocatedCwd` emits nothing (counted as dropped).
