# ICR 0009 (WP-09): L2 core — one additive model change, private additions, and conventions other packages rely on

- **Status:** accepted (2026-11-03, WP-09, additive only)
- **Files:** `src/model/state.ts` (one optional field); WP-09's own `src/core/**`, `test/unit/core/**`

## 1. Additive model change

`SessionState.inputBlocked.editor?: boolean` (ICR 0001 item 3c, LP-01). Set when an `editorOpen` surface lasts longer than
`editorConsumeMs` with no library job running (a human pressed `C-g`); `canSubmit` is then false (clause `editorOpen`) and a
`warning{code:'E_INPUT_GATED', detail.reason:'editorOpen'}` is published (never `unsupportedRenderer`). Optional so every
existing constructor of `inputBlocked` stays valid. `ScreenFacts.surface 'editorOpen'` was already added by ICR 0007.

## 2. Private additions inside `src/core/**` (no other package needs to change)

- Three helper modules not named in §1.2: `core/types.ts` (the §2.9 types `CoreState`, `ReconState`, `Counters`,
  `CoreInput`, `StepResult`, `NextDeadline`, plus `DetailedStepResult`; `core/step.ts` re-exports them together with
  `CoreInit`, `Diagnostic`, `initialCore` and `nextDeadline`, so L3 imports the whole §2.9 contract from `core/step.ts`), `core/ctx.ts` (the per-step context: the only
  route to `evolve`) and `core/decide/entities.ts` (lattice-checked entity writes shared by the decide modules). They exist
  because `decide/*` must name `CoreState` without an import cycle through `step.ts` (depcruise `no-circular`).
- `InputJob = InputJobSpec & JobRuntime`: `InputJobSpec` is the §2.9 union verbatim; `JobRuntime` adds bookkeeping
  (pending intent, frame wait, clear sub-sequence, retries, fallbacks). `InputPolicyState` gains `pendingResults`.
- `ReconState` gains private bookkeeping fields (launch parameters, transport health, pending transcript prompts,
  `msgCall`, `txWalls`, `stopUncorroborated`, `permAgentId` (the raw `agent_id` a PermissionRequest carried), …); all JSON data, so `serializeCore` stays a plain JSON round trip (I7).
- `stepDetailed(core, input)` = `step` plus the folded `CoreEvent[]` (used by the I1 property test and trace tooling).
- `x.patch.patch` is `{op:'set', value, why} | {op:'unset', why}`; `entity` is a '/'-joined path, JSON-pointer escaped
  (`~0`, `~1`). Every domain change is an `x.*` event; published `DomainEvent`s advance `lastEventSeq` (and
  `status.changed` sets `status`), so `fold(evolve, initialDomain, coreEvents)` equals `core.domain` by construction (I1).

## 3. Conventions WP-11 / WP-12 / WP-13 / WP-14 / WP-15 rely on

1. **Deferred command results.** `slash.run` and `mode.set` resolve when their job ends, in a *later* step's
   `commandResult` carrying the original `cmdId`. If two results become due in one step, the second is queued and the core
   arms a mono deadline at `now`, so the scheduler (A-0) runs a `clock.tick` that delivers it. All other commands resolve
   in their own step.
2. **Frame waits.** A job that needs to look at the screen emits `screen.captureNow{reason:'job:<purpose>'}` and accepts
   the first non-torn frame with `meta.at ≥` the request time; because L1 drops identical frames, after 600 ms it uses the
   last frame it has. With the screen transport `down`/`off` it proceeds without frame checks. The core never asks for a
   capture while `awaitEditorConsumed` is pending (ICR 0001 item 3d): the executor must report `input.done` for it.
3. **`inputBlocked.permission`** is true only while a PermissionRequest is *held* (state `pending`, has a `hookSeq`). An
   answered request no longer blocks keys; a visible native dialog (`dialogOnly`) is `inputBlocked.dialog`. Invariant I6 is
   enforced at emission: every key except `Escape` (Enter, digits, `BTab`, `C-g`, `Up`/`Down`) and every text primitive
   while a request is held is withheld (diagnostic `I6_guard`) and re-sent when the hold ends.
4. **Close.** `session.close` is decided in core: `waitForBackgroundMs` (graceful only) waits on a `drain` deadline or
   quiescence; then `session.closing`, every held request denied (`by:'close'`), queued library turns `aborted
   {E_SESSION_CLOSED}`, and either an internal `/exit` command job (ready, idle, clean composer, no dialog) or
   `process.signal SIGTERM`; `mode:'kill'` → `process.signal SIGKILL`. A failed `/exit` job → `SIGTERM`. L3 still owns the
   pane-dead wait, the second SIGTERM/SIGKILL escalation and cleanup (§3.8).
5. **Startup failures** are published, not thrown: `session.gated{gate,text}` (lifecycle `gated`; L3 maps the gate and kills
   the pane); `warning E_STARTUP_TIMEOUT{phase,screenSummary}` and `warning E_SELFTEST_FAILED{step,transcriptEvidence,
   hookTransport}` are each followed by `session.exited{reason:'startupFailed'}` and `lifecycle.finalize`; L3 rejects
   `start()` and performs the one automatic `unix` relaunch when `step:'ack'` and `transcriptEvidence:true` (§3.1 step 15).
6. **Self-test nonce.** Besides the nonces this core armed, any prompt of the exact shape `^ccd-selftest-[0-9a-f]{32}$` is
   never a Turn (K-50 across starts). `prompt.blocked` (ICR 0002) for the nonce is the transcript cross-check; for a user
   prompt it is evidence for `E_TURN_BLOCKED_BY_HOOK` (the turn ends `notSubmitted`, the composer is cleared).
7. **Commands.** The alias, allow, deny and refuse tables come from `CoreConfig.commands` (WP-11 `DEFAULTS` should carry
   ICR 0001 item 6: allow `/usage` instead of `/cost`, aliases `/cost`,`/stats`→`/usage`). Independently of the config the
   core refuses `/exit`, `/quit`, `/tui`, `/restart`, `/resume`, `/rewind` even with `unsafe`, on both the raw and the
   canonical name, so a gap in the alias table cannot bypass it.
8. **Forged-Stop guard (K-32).** A turn completed by `Stop` lets the library queue drain only after corroboration (a
   `turn_duration`, a screen done line, or an idle main frame) or after `transcriptSettleMs` (diagnostic
   `stop_uncorroborated`).
9. **Permission timeouts.** Any request that carries an `agent_id`, or whose bound tool belongs to a background agent,
   uses `backgroundTimeoutMs` (§3.7 step 10).
10. **Replay.** Observations with `meta.replay` only feed the uuid de-dup set and the permission-mode fact; history never
    re-creates turns, tools or agents (no stale `activeTurn` can block the queue after a resume).
11. **Screen claims TTL.** Frames arrive only on change, so an asserted claim still shown by the latest frame of a healthy
    screen channel is extended at its TTL; it expires when a newer frame no longer shows it, or at the TTL when the screen
    transport is not `up`.
12. **Interrupt jobs re-check busyness when they start.** An interrupt queued behind another job (typically our submit
    waiting for its UPS ack, P-INPUT-23) that finds no active turn when it starts ends with `interrupt.ignored{notBusy}`
    and presses nothing (an Escape on an idle composer would clear a draft or, after a clear's Esc-Esc, open Rewind).
13. **Permission binding with a carried `agent_id`** (P-REC-44) matches only tools of the agent with that raw id; a request
    from a not-yet-known agent is `unbound` (auto-answer off) and binds on that agent's late PreToolUse, never on an
    identical main-thread tool. An attachment that names the other tool of an `ambiguous-equivalent` guess emits
    `permission.rebound` (§4.5.1).
14. **`/model` side effect.** A transcript `<local-command-stdout>` of `/model` containing `saved as your default` publishes
    `session.modelChanged{source:'command', savedAsDefault:true}` and `warning{detail.reason:'modelSavedAsDefault'}`
    (§3.6 Commands, LC §10.3).
