# ICR 0015 (WP-15): public API conventions other packages rely on

- **Status:** accepted (2026-11-03, WP-15). No change to `src/model/**`.
- **Files:** `src/api/**`, `etc/claude-code-driver.api.d.ts`, `test/unit/api/**`.

1. **How `ClaudeSession.start()` reaches `createKernel` (WP-INT).** `src/api/claude-session.ts` loads `../runtime/node.js` on the
   first `start()` through a variable specifier (same convention as `testing/test-kernel.ts`, ICR 0014 item 1), so the package
   type-checks before WP-INT lands. It calls `createKernel(spec, { logger?, signal? })` and expects a kernel that resolves at
   ready (§2.10). A missing module or export surfaces as `E_INTERNAL{reason:'E_INVARIANT'}`. Once `runtime/node.ts` exists, WP-INT
   may replace the loader with a static import; nothing else changes. Test seams (not re-exported from `index.ts`):
   `setKernelFactory(f)` and `wrapKernel(kernel, options)`.
2. **Declaration hygiene (§1.3 leak grep).** Every file reachable from `dist/api/index.d.ts` (`index`, `claude-session`,
   `options`, `public-types`, `map-errors`, `iterators`) names no internal type in an exported signature. `map-events.ts`,
   `map-state.ts` and `turn.ts` are implementation-only and never imported by those declarations. Consequences:
   `toSessionSpec()` returns `MappedOptions` whose `spec` is typed as a plain record (it is built as a `SessionSpec`;
   `claude-session.ts` is the one place that casts it back), and `redactEvent` lives in `iterators.ts`.
3. **The facade's subscription.** It subscribes with `fromSeq = state.lastEventSeq` (inclusive) right after creation; the replay of
   that last pre-start event only anchors the mono → wall offset (`wallAt − at`) and is not delivered. Public `at`, `since`,
   `startedAt`, `requestedAt` and `deadlineAt` are wall-clock epoch ms derived that way. Events with `replayed: true` are dropped
   unless the caller asks for `events({ fromSeq: 0 })` (P-API-22).
4. **Turn keys.** `send()` dispatches `prompt.send` with `clientRef = 'pending:<n>'` and returns at once; the turn binds to its
   core `TurnKey` from `turn.queued.payload.clientRef` (or the dispatch result, whichever comes first). Until then `turn.key` is
   the `pending:<n>` reference. **Core must echo `clientRef` in `turn.queued`** for events published before the dispatch resolves
   to reach the handle.
5. **`closeAll()` across package copies (P-REV-43).** Live facade sessions are kept in
   `globalThis[Symbol.for('claude-code-driver.api-sessions.v1')]` (a `Set` of objects with `close(opts?)`), separate from L3's
   exit-cleanup registry (`…exit-registry.v1`, owned by `session/lifecycle.ts`). `installSignalHandlers()` is implemented in the
   facade on top of that set (the api layer may not import `session/**`); it uses no timer (§4.12 closed list) and relies on the
   kernel's own SIGTERM → SIGKILL escalation (D-27) to bound a graceful close.
6. **Public permission decisions** carry no `updatedPermissions`; the facade passes the user's decision to the kernel unchanged.
   A throwing or rejecting user handler fails closed (`deny`, logged).
7. **Error sub-reasons (verifier pass).** Public `details.reason` is always the internal `CcdErrorCode` (§2.2). An L3/L2 error
   that recorded its own sub-reason under `details.reason` (`session/config.ts`: `permissionsRequired`, `unknownKey`,
   `notAllowlisted`, `forbiddenName`, `dangerousMode`, …) keeps it as `details.detail`; the facade's own validation errors use the
   same key (`E_CONFIG{reason:'E_CONFIG_INVALID', detail:'permissionsRequired', path:'permissions'}`, matching §3.1).
8. **`exited` is always delivered.** When `close()` resolves before the facade's subscription received `session.exited`, the facade
   emits one `exited` event itself (same data as the resolved `SessionExitInfo`) and then unsubscribes, so it is never duplicated.
   `events({ fromSeq })` opened after the exit with a `fromSeq` past the exit ends at once. The public declarations do not depend
   on `@types/node` (`SignalProcess` uses the local `HandledSignal` union).
